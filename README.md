# maximotools

**A version-aware testing kit for IBM Maximo / MAS Manage.** Stop queueing
for the shared QA instance: capture the metadata of the Maximo you actually
run, then test against evidence — an HTTP stub for the conversations other
systems have with Maximo, and Mockito MBO mocks for the logic you wrote
inside it. Targets MAS **9.1** and **9.2** first, with classic **7.6.1**
supported as a lens label.

The design follows three published field guides — read them for the why:

- [Test stubs, done properly](https://assetize.com.au/test-stubs)
- [Mockito MBO kit](https://assetize.com.au/test-stubs/mockito)
- [Metadata APIs — MXINTOBJECT & friends](https://assetize.com.au/test-stubs/mxintobject)

The discipline in one paragraph: **every fixture and every mock behaviour is
tagged with the release lenses it is evidenced for, and carries the
provenance of that evidence. When a test asks for a lens nothing is
evidenced for, the kit fails closed** — an explicit error naming what the
evidence covers, never a silently reused response from another release
line. An unversioned fixture is a rumour with a JSON extension.

## The flow

```
 1. capture                2. dictionaries/            3. consume

│ capture.mjs 9.1 │ ───▶  │ 9.1/systeminfo   │ ───▶  │ stub/   (HTTP surface)│
│ (read-only GETs │       │ 9.1/mxobjectcfg  │       │ mockkit/ (MBO logic)  │
│  against a live │       │ 9.1/schemas/*    │       │ …your CI matrix per   │
│  instance)      │       │ + provenance     │       │  lens                 │
└─────────────────┘       └──────────────────┘       └───────────────────────┘
```

## Quickstart

Everything runs out of the box against the committed
`dictionaries/_synthetic` samples and synthetic starter fixtures — both
clearly labelled `SYNTHETIC_PLACEHOLDER`, and both gated so nothing
synthetic is ever mistaken for evidence.

### 1. Capture a real lens (`capture/`) — Node 20+, zero dependencies

```bash
export MAXIMO_BASE_URL=https://your-maximo.example.com/maximo
export MAXIMO_APIKEY=...            # environment only; never a CLI arg or file
node capture/capture.mjs 9.1        # writes dictionaries/9.1/
```

Captures `/oslc/systeminfo`, `/oslc/apimeta`, the `/api/os/mxintobject`
roster, `/oslc/jsonschemas/{os}` per rostered object structure, and the
`/api/os/mxobjectcfg` attribute dictionary. Read-only GETs only — the tool
has no write code path. Every file carries a provenance header (source
host, capture date, build string, sha256 of the raw response). Re-running
against an instance whose build string differs from the existing capture
refuses unless you pass `--refresh`.

### 2. Serve the HTTP surface (`stub/`) — Node 20+, zero dependencies

```bash
node stub/server.mjs --lens 9.1 --allow-synthetic     # starter fixtures
curl -H 'x-version-lens: 9.1' localhost:8009/api/os/mxapiasset
curl -H 'x-version-lens: 7.6.1' localhost:8009/api/os/mxapiasset
# → 409 NO_FIXTURE_FOR_VERSION, naming the lenses evidence covers
```

- lens per request via `x-version-lens` (fallback: `--lens`);
- **fail closed**: unevidenced lens → explicit `409 NO_FIXTURE_FOR_VERSION`
  listing covered lenses — never a reused response;
- fixtures are validated against the captured JSON schemas at startup; the
  server refuses to start on a mismatch;
- `SYNTHETIC_PLACEHOLDER` fixtures are refused unless started with
  `--allow-synthetic`.

### 3. Mock the inside (`mockkit/`) — Java 17, Maven

```bash
cd mockkit
mvn -q -pl core verify                     # no IBM JARs needed, lens 9.1
mvn -q -pl core -Dmaximo.lens=9.2 verify   # lens 9.2
```

Fluent `MockMboSet` builder over Mockito 5 + JUnit 5, with a fail-closed
attribute dictionary generated by the capture pipeline, and the
`@EvidencedOn` extension that skips loudly on unevidenced lenses and fails
tests that claim no evidence at all. IBM-typed adapters live in
file-activated profile modules — see [mockkit/README.md](mockkit/README.md)
and [mockkit/libs/README.md](mockkit/libs/README.md) (extraction from an
admin pod; **IBM JARs are never committed**).

## Tests

```bash
node --test capture/test/    # offline; recorded/synthetic inputs, no network
node --test stub/test/       # offline
cd mockkit && mvn -q -pl core verify
```

## The two-lens CI matrix

Run the same suites once per lens, so a divergence between release lines is
a visible red/skip, not a silent pass ([workflow](.github/workflows/ci.yml)):

```yaml
strategy:
  matrix:
    lens: ["9.1", "9.2"]
steps:
  - run: node --test capture/test/ && node --test stub/test/
  - run: mvn -q -pl core -Dmaximo.lens=${{ matrix.lens }} verify
    working-directory: mockkit
```

Tests evidenced for one lens only (`@EvidencedOn({"9.2"})`, fixtures with
`"versions": ["9.2"]`) execute in that lens's job and skip loudly in the
other. One more habit pays for the rest: periodically re-run the capture
and diff the sha256s — a changed hash is the release notes you didn't read,
surfaced by your test suite, with the release line named.

## Ground rules

- **No secrets anywhere.** Real URL and API key are supplied as environment
  values at run time; nothing secret (including realistic-looking
  placeholder keys) goes in code, fixtures, docs, tests or history.
- **Evidence discipline.** Response shapes are never invented and presented
  as real. Synthetic placeholders are labelled `SYNTHETIC_PLACEHOLDER` and
  gated. No claim about version-specific behaviour without a captured
  source.
- **No IBM binaries or IBM documentation text** in the repository — links
  only. `mockkit/libs/` is gitignored for a reason.
